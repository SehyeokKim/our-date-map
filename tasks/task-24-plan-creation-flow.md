# Task 24 — 데이트 플래너 플랜 생성/편집 시나리오 재정립

## 목표
플랜 추가부터 경유지 등록·저장까지의 흐름을 아래 시나리오대로 재정리한다.

1. **플랜 추가** 버튼 → 일정 생성 모달(현행 유지)
2. 시작일·종료일·제목 입력 → **이 시점에 DB에 일정이 생성**되어 일정 목록에 바로 나타난다
3. 하단 코스 시트에서 경유지를 추가한다
   - 3-1. 시트의 편집 토글을 눌러 편집 상태로 들어가며, **"완료"를 누르면 변경사항이 DB에 저장**된다
4. **지도 클릭으로 장소를 추가하던 방식 폐지** — 경유지는 편집 상태의 "경유지 추가" 버튼으로만 추가
   - 4-1. 경유지 추가 창의 **"핀으로 추가"** 버튼으로 지도에 직접 핀을 찍어 등록할 수 있다(주소를 모르는 경우)

## 설계 결정
- **편집 상태 관리 위치:** 기존에는 `FuturePlanSheet` 내부 state였으나, 새 플랜 생성 직후 자동으로 편집 상태로 진입해야 하므로 `page.tsx`로 끌어올린다. 시트는 `isEditing` / `onToggleEdit`를 props로 받는다.
- **버튼 라벨:** 편집 중이면 `완료`(저장), 아니면 `수정`(편집 진입). 새 플랜을 만들면 곧바로 편집 상태이므로 시나리오상 사용자는 `완료`부터 보게 된다. 이미 저장된 플랜을 다시 손볼 수 있어야 하므로 `수정` 진입점은 유지한다.
- **지도 핀 허용 조건:** `useKakaoMap`이 `allowMapPin`을 받아 클릭 리스너에서 게이트한다. 추억 모드는 항상 허용, 플래너 모드는 **핀 선택 모드일 때만** 허용.
- **DB 스키마 변경 없음:** `date_plans`의 기존 컬럼(`title`, `start_date`, `end_date`, `spots`, `route_summary`)만 사용한다. 마이그레이션 불필요 → `!DB` 플래그 대상 아님.
